# NES (6502 / PPU)

## CPU
- MOS 6502 @ ~1.79 MHz (NTSC), ~1.66 MHz (PAL).
- 56 instructions, no multiply/divide, 3 registers (A, X, Y).
- Zero page ($00–$FF) is faster than absolute addressing; use it for hot variables.

## PPU / video limits (hard rule #3)

| Limit | Value |
|---|---|
| Sprites total | 64 |
| Sprites per scanline | 8 |
| Sprite colors | 3 + transparency |
| Background palettes | 4 × 4 colors |
| Sprite palettes | 4 × 4 colors |
| Nametables | 2 (2K each) |
| CHR ROM/RAM | 8 KiB tiles (bankable via mapper) |

## Mapper (mandatory first fact)

- No mapper = 32 KiB PRG + 8 KiB CHR fixed.
- Common mappers: UxROM (2), MMC1 (1), MMC3 (4), MMC5 (5), AxROM (7), UNROM (2).
- The mapper determines PRG/CHR banking; name it before writing code (hard rule #1).

## Timing budget

- NTSC frame: ~29,780 CPU cycles (60.1 Hz).
- Vblank: ~2,273 cycles for VRAM/OAM/Palette updates.
- OAM DMA: 513 or 514 cycles, must run during vblank.

## Sprite 0 hit

- The scanline IRQ primitive for splits/parallax. One per frame, fires when opaque
  sprite 0 pixel overlaps opaque background pixel.

## Toolchain

- ca65/cc65 is mainstream; asm6 and NESASM are alternatives.

## Common failure

- Writing VRAM outside vblank → garbled screen on real hardware.
- Exceeding 8 sprites/scanline → flicker (not a bug, the medium).
